## 2. 不强行塞进章节的内容

- 王道的“发展历程、系统分类”与课程顺序不同：基础多道/分时可放第 1 章，批处理细分等放课程补充标签。
- ch1 的虚拟机/VMM 题不能因为出现在上游第一章就视为用户已学。笔记中仅有概览时，标记补充内容并列明知识要求。
- 原站备考指南、考纲、真题统计属于“原题库参考资料”，不作为大学课程必修任务。
- Linux 内核重建、OpenMP、线程库、NFS 等若缺对应题，显示覆盖缺口。不得用无关题凑数。
- 第一章提到进程、内存、文件等概念，不意味着相应算法、数据结构和综合题的前置知识已经学完。

## 3. 逐题映射记录

每道题至少保存：

| 字段 | 含义 |
|---|---|
| `questionId` | 从原题目登记表分配后冻结的唯一 ID，不使用新页面中的第几题 |
| `primaryChapterId` | 主要归属章节，只有一个；不能确定时暂留 unmapped |
| `secondaryChapterIds` | 可用于其他章节复习的交叉索引，不复制题目实体 |
| `topicIds` | 对应笔记真实小节的知识点 |
| `prerequisiteTopicIds` | 正确完成题目需要的全部知识点 |
| `readinessTier` | core / bridge / later / supplement / disputed |
| `mappingReason` | 为什么归到该章，以及与笔记的联系 |
| `mappingStatus` | candidate / reviewed / unresolved / outside-course |
| `reviewEvidence` | 笔记文件、小节和必要的教材/规范依据 |

判断“现在能做”时不能只看 `primaryChapterId <= 当前章`。具体定义：前置知识已确认覆盖，或被列为本轮桥接练习；存在争议的题排除自动计分。

只有章完成状态、没有小节记录时，明确映射为该章核心内容的知识点可视为覆盖；补充标签和后续章知识不能被顺带解锁。

## 5. 题目数量和学习进度的展示

- 每章分别显示：核心可做、需要桥接、稍后再做、待审题、已做、错题。
- 一道题在两章出现，学习记录仍只有一份，整库统计按唯一 ID 去重。
- “读过笔记”“做过题”“做对题”“人工确认掌握”是不同状态。
- 15 章和补充章可能有不同题量；章节没有对应题时明确显示覆盖不足。
- 初始化只将第 1 章标记为用户已确认学完。后续章节默认 unknown，由用户更新。
