## 4. 技术路线与取舍

采用静态站点 + 结构化数据 + 前端本地记录。优先复用原站的 HTML 内容和视觉基础，避免为分章练习引入不必要的服务端。

- 提取与构建：Python + Beautiful Soup，依赖显式记录并固定可复现版本。
- 页面：普通 HTML、CSS、JavaScript ES Modules；共用组件放独立模块，不在每页复制大段脚本。
- 数据：JSON，题干和解析保留受控 HTML，以保留表格、公式、代码和配图。
- 公式：KaTeX 资源本地化；实施时确认所用版本的依赖、许可和发布说明，再锁定版本。
- 本地运行：只绑定 `127.0.0.1` 的 HTTP 服务，通过启动脚本稳定使用同一 origin。
- 记录：先用 localStorage 的版本化存储；导入导出 JSON 作为跨浏览器备份方式。
- 验证：Python 数据校验 + 浏览器完整流程验证；没有真实需要时不加后端或庞大测试框架。

暂不引入：登录、云数据库、自动同步个人学习数据、LLM 自动判分、Service Worker/PWA、复杂打包框架。后续若实际需求变化，在决策记录中说明理由再扩展。

不把“原站可以在浏览器打开”当成适配已完成；适配后必须从课程章节完成选题、作答、刷新恢复与错题回顾。

## 5. 数据设计

### 5.1 题目数据

正式文件规划：

- `data/questions.json`：原始结构化题目实体，每题只存一份。
- `data/source-registry.json`：稳定 ID 与原来源定位、内容哈希的登记表。
- `data/chapters.json`：本地课程章节与补充章。
- `data/topics.json`：依据笔记真实小节建立的知识点。
- `data/mappings.json`：主归属、交叉关联、前置知识、学习分层、审核状态。
- `data/overrides/errata.json`：本地勘误与争议记录。
- `data/coverage-report.json`：题量、映射、缺口、题型与审核状态汇总。
- `data/study-defaults.json`：只包含用户确认的初始进度，不伪造作答历史。

题目至少包含：

```json
{
  "id": "从登记表分配并冻结的ID",
  "type": "single_choice | multi_blank | constructed_response | unresolved",
  "source": {
    "repository": "jlshdsdk/kaoyan-408-os",
    "revision": "e360b96fbd6522656d633ad9e26b7dd91f7bd1b4",
    "path": "ch1/quiz.html",
    "sectionId": "toc-3",
    "originalLabel": "第 9 题",
    "originalContentHash": "用于比对变更，不作为可随意重算的身份"
  },
  "stemHtml": "保留原题干结构",
  "options": [],
  "originalAnswer": "原站答案",
  "originalExplanationHtml": "原站解析",
  "assets": [],
  "reviewStatus": "unreviewed | verified | disputed | corrected"
}
```

调查目录中的 `provisional_id` 只用于当前盘点，不宣称未来可以随页面标题/顺序变化重算。正式 ID 初次登记后固定；上游插入、移动、删除题目时通过来源定位和内容差异协调迁移。

### 5.2 内容提取

1. 按 `article` 内 H2/H3 和 `details.qa` 的边界提取，不使用仅 `.q` 的方案。
2. `.q` 容器题与独立综合题采用不同边界识别；构建完整题干节点集合，不仅拿最后一个段落。
3. 保留所有子问、题目前提、表格、甘特图、公式分隔符、代码、图示和答案过程。
4. 剥离脚本、事件处理属性、原站导航与练习状态逻辑；HTML 内容转换必须有白名单，不能把整个原页面塞进运行界面。
5. 资源链接改写到可解析的本地相对路径；确保图片和公式字体从不同子路径打开仍正常。
6. 5 个特殊题逐一确定交互；无法可靠识别的题保留为阅览/自评，不静默丢掉或错判。
7. 760 是来源题块基线。若后续确认重复题，保留全部来源条目，另设去重关系，不直接减少导入数量。

### 5.3 勘误与语境

每条勘误记录：题目 ID、原答案/表述、疑点、审核状态、来源链接或本地笔记小节、必要的体系结构/调度假设、本地展示建议、审核日期。

- 不覆盖 `vendor`，也不悄悄覆盖 `originalAnswer`。
- 有可信依据时显示“原答案”和“本地修订”及修订依据。
- 只有疑点时显示“待核对”，不自动加入计分练习。
- 真题年份在核对前显示“原站标注年份”，不写成已核实真题。
- 区分教材简化模型与现实中的微内核驱动、RISC-V/x86 差异。

## 7. 练习界面与个人学习流程

优先实现：

- 首页：当前学习章节、第一章可做题、继续练习入口。
- 课程导航：15 章 + 补充章，标题与本地笔记一致。
- 每章：核心练习、桥接练习、后续知识、待审题及题量说明。
- 题目卡：原来源定位、对应笔记小节、当前是否可做和原因、题干/选项、答案与解析。
- 单选：提交后判分，保存实际选择、首次结果和最近结果；不只保存对错。
- 多空题：按字段记录并明确判分规则；未确定类型时关闭自动计分。
- 综合题：先独立思考，再展开解析、自评；没有自动正确性判定。
- 错题/收藏：按稳定 ID 聚合，支持再次作答和个人备注。
- 搜索：章节、题干、知识点、原题号；结果能直接定位到当前题目。
- 原题库入口：仍可按原 5 章阅读完整内容，保留参考工具页。
- 笔记跳转：通过可配置本地笔记路径/Obsidian URI；未确认 vault 标识前不硬编码可用链接。

进度管理：

- 使用独立命名空间 `os-exercises:v1`，不覆盖原站 `os408-*` 记录。
- 稳定 origin，避免切换端口或 host 后看似丢失学习记录。
- 存储失败时显式提示，不能让用户误以为已自动保存。
- 导出含 schemaVersion、数据集版本和时间；导入先校验版本、ID 和字段，再选择合并，不直接清空旧记录。
- 同一题重新归章或上游更新后，原作答仍可追溯；删除的题保留历史说明。
- 初始实施不读取或迁移旧站 localStorage：它没有完整选项历史，贸然映射会制造错误记录。

## 10. Git 与 GitHub 工作方式

- `origin` 为新私有仓库，不能将源仓库设置成推送目标。
- 首次提交包含原快照、计划、调查和目录约定，作为可回退基线。
- 后续按 P1～P5 分可审核提交；每个提交说明实际完成的行为与验证，不写尚未执行的结果。
- 需要隔离较大改动时使用功能分支；不提前创建空 PR。若实际创建 PR，再在聊天中附上链接。

## 11. 上游更新与回退

更新流程：

1. 获取上游新提交到 `_work/upstream.git`，先记录新旧提交与文件差异。
2. 对新增、修改、删除题目生成报告；对疑似同题移动和内容更改进行人工确认。
3. 保持旧题 ID；新题分配新 ID；删除来源条目不删除历史作答。
4. 勘误和人工映射独立保留；上游修改答案后重新审核相关 override。
5. 在功能分支更新原快照和 manifest，跑相关数据与浏览器检查。
6. 更新 `docs/调查记录.md` 与维护记录后再合入。

回退：使用 Git 还原适配代码/数据版本；用户学习数据先导出，迁移保留旧 schema 副本。不要通过删掉 `personal/` 或清空 localStorage 来“修复”失败。原 Obsidian 笔记不需要回退，因为从不写入。

新机器重建上游镜像（这是将来需要时的命令，不是自动更新操作）：

```powershell
git clone --mirror https://github.com/jlshdsdk/kaoyan-408-os.git _work/upstream.git
git --git-dir=_work/upstream.git cat-file -e e360b96fbd6522656d633ad9e26b7dd91f7bd1b4
```

实际导入时使用明确提交与 `-c core.autocrlf=false`，不能直接以变化中的 HEAD 替换已锁定快照。
