# 课程题库适配与练习站建设复用指南

整理日期：2026-10-23。用途：交给新的 AI 对话，仿照本项目为其他课程完成“收集来源 → 保真提取 → 对齐笔记 → 逐题审核 → 练习闭环 → 验证发布”。

本指南同时包含本项目的实际经历和可复用流程。实际状态核对基线为 OS 项目提交 307d259；本文是其后的新增文档，不表示在该提交中已经存在。其他课程的目录、题型、章节、许可和审核结论必须重新调查。

**建议新对话先读第 1、3、4、15 节，再按第 5～12 节实施。不要只复制网页，也不要把本项目的答案结论和学习进度复制到另一门课。**

## 1. 要完成的工作是什么

目标是把现有题库变成能够跟随用户实际课程学习的练习工具，同时保留来源、原题和历史记录。

最终至少交付：

1. 一份版本固定、可以校验的原始资料快照。
2. 一份能回溯到原题位置、保留复杂结构的结构化题库。
3. 用户笔记的真实章节和知识点目录，以及逐题对应关系。
4. 原答案之外独立保存的审核结论、前提说明和勘误。
5. 一个先能完成首章练习闭环的网站，再逐步扩展。
6. 可重复执行的校验、构建、发布流程，以及接手者看得懂的文档。

需要始终区分六件事：

| 维度 | 回答的问题 | 不能替代什么 |
|---|---|---|
| 来源保真 | 是否忠实保留了原题和原答案？ | 不代表原答案正确 |
| 章节映射 | 这道题考什么，对应哪份笔记？ | 不代表用户已经学会 |
| 学习范围 | 现在适合练核心、桥接还是补充？ | 不代表审核可靠性 |
| 答案审核 | 在什么模型和前提下，答案是否成立？ | 不代表官方勘误 |
| 判分策略 | 此题能否自动判分，采用什么规则？ | 不等于有没有参考答案 |
| 实测状态 | 哪些文件、交互和线上版本通过了什么验证？ | 不等于所有平台都能正常使用 |

“已结构化”“已映射”“逐题读过”“独立复算过”“已发布”应分别记录，不能合并成一句“全部完成”。

## 2. OS 项目从零到现在的实际过程

### 2.1 先恢复上下文，确定原题库与启动方式

最初用户引用了“搜索王道OS”“查询启动命令”两段历史对话，想知道学完课程第一章后能练哪些题。

当时的读取问题是：工具返回了对话和用户消息，但助手正文只有内容引用标记。请求成功并不代表正文可见。最终在用户本机已有的目标对话缓存中恢复了两段对话的正文，找到此前讨论的题库和启动信息。

可复用经验：

- 先检查返回的内容是不是实际正文，不要把引用标记、标题或摘要当作答案。
- 常规读取与分页仍无正文时，再考虑针对用户指定对话的本机恢复；这是特定机器和版本下的排障方法，不是每门课的必经步骤。
- 缓存恢复只处理指定目标，核对对话 ID 和正文，保留必要证据；不要收集无关聊天、认证信息或整个浏览器资料目录。
- 恢复出的历史内容只帮助定位来源，当前任务仍以用户指令和实际文件为准。

### 2.2 建仓之前先查结构，先把计划写进文件

用户要求把题库迁入本地 exercises 下的新文件夹，适配 Obsidian 笔记，并同步 GitHub。

当时 OS 上级目录不是 Git 仓库，随后明确了账号 dou307、仓库名 os-exercises、初始私有可见性。本地项目统一放到：

~~~text
D:\desk\1learn\OS\exercises\os-exercises
~~~

先建立来源基线、调查记录、实施计划和执行清单，再交给后续对话实施。用户需要自己使用 exercises，因此没有把脚本、缓存、截图散放到上级。

调查确认：

- 上游为 jlshdsdk/kaoyan-408-os，锁定提交 e360b96fbd6522656d633ad9e26b7dd91f7bd1b4。
- 原始快照有 176 个文件、38 个 HTML、135 张图片。
- 答案块有 760 个，而常见题目容器 .q 只有 713 个。
- 另外 47 道综合题采用独立结构；只抓 .q 会漏题。
- 645 道可识别为普通单选，5 道属于多空/复合形式，110 道为综合题。
- 来源按 5 章组织，本地笔记为 15 个主章节加 2.1 补充章，不能直接一一改目录名。

### 2.3 保留原始层，另建提取、映射和勘误层

原站完整放入 vendor，提取为结构化数据；课程章节、知识点、审核和练习状态分别保存。

遇到过 Windows 自动换行转换：文件看起来相同，但 CSS 的字节已经与上游不同。处理办法是以禁用换行转换的 Git 归档方式取得快照，设置 vendor/** -text，并逐文件对比上游 blob。

还专门处理了：

- 无 .q 容器的独立综合题。
- 罗马数字陈述列表与真正 A、B、C、D 选项的区别。
- 表格、代码、公式及其顺序。
- 题号标签与题干正文的分离。
- 特殊题型保留原结构，不能强行当作普通单选判分。
- 题目 ID 首次分配后登记冻结，不随课程重新排序而变化。

### 2.4 先打通课程第一章，再扩展全库

用户只确认课程第一章 Introduction 已学完，因此初始学习事实只保存这一条。

来源第一章共 88 题，逐题归属后，课程第一章页面收录 56 题，其余 32 题归到课程第 2、3 章。不是丢了 32 题。

当前第一章页面采用互斥分组：

| 分组 | 数量 | 练习方式 |
|---|---:|---|
| 核心 | 40 | 39 道单选自动判分，1 道综合题自评 |
| 桥接 | 1 | 提示后续前置知识，可提前接触 |
| 补充 | 12 | 额外范围，包含需要自评的特殊题 |
| 待核对 | 3 | 保留原题，独立列出，不自动计分 |

核心练习入口包含核心与桥接，共 41 题。历史映射里的 core 42、bridge 1、supplement 13 包含了后来单列的争议题，与页面口径不同，不能简单说数据矛盾。

“桥接”表示与当前课程有关、但仍需要后续或额外知识的练习；它不是答案正确认证，也不是普通难度标签。

首章闭环包括：进入章节 → 选择范围 → 作答 → 提交/自评 → 查看解析 → 刷新恢复 → 错题回顾 → 重做 → 导出/导入记录。

### 2.5 接手审查时，重新验证此前的“完成”

后续对话根据交接文件审查网站，没有把旧报告当作充分证据。

发现原校验只看题干前缀，不能发现长题尾部丢失；只检查少数 quiz 文件，也不能保证整份来源快照未变。随后增加独立全文与结构校验、全部来源字节校验、稳定 ID 回归，并修复记录迁移、错题重做、搜索、路由竞争和移动端问题。

期间发现另一个进程仍在修改 app.js、practice.js 等文件。先保留已有修改与备份，再请用户暂停其他 AI 写入，确认后继续整合。没有用 reset 或 checkout 丢弃别人的工作。

经验是：**文件正在变化时，先确认写入者和基线；不能一边互相覆盖一边声称完成了审查。**

### 2.6 来源第二、三章逐题审核

2026-10-23 继续按题干、选项、原答案、完整解析、课程笔记和前置知识逐题审核：

| 来源章节 | 题数 | 未发现实质问题 | 附前提/解析勘误 | 争议不计分 | 勘误/前提条目 |
|---|---:|---:|---:|---:|---:|
| 第二章 | 276 | 179 | 74 | 23 | 97 |
| 第三章 | 166 | 90 | 65 | 11 | 76 |

第二章另做 31 组独立复算/有限反例，第三章做 56 组。它们针对具体题目及模型，不表示用有限测试证明了全部理论。

第三章是来源“内存管理”，映射到课程第 2、9、10 章，不是课程笔记第 3 章“进程”。分段内容出现在真实笔记的补充 callout 中，不能为了凑映射凭空创建一个已经存在的小节。

审核中进一步修复：

- 归属理由和详细勘误可能包含答案，作答前隐藏，随解析展开。
- 旧版本已自动判分的题后来被认定争议时，保留原始历史记录，但从当前自动判分统计中排除。
- 不把“教材模型下成立”改写成适用于所有现代系统的结论。

### 2.7 发布和使用中的增量优化

仓库初建时为私有，后经用户明确选择改为公开并上线 GitHub Pages。现在的公开状态不能倒推为最初已经授权，也不能作为其他课程默认公开的理由。

实际采用 main 推送后构建 dist 并发布；本地提交、远端提交、Actions 成功、线上实际内容分别核验。

最后一项界面改动是在题卡底部右侧增加题号跳转、上一题和下一题，与顶部共用导航逻辑，验证首末题禁用、回车跳转和窄屏布局。

### 2.8 截至本指南的真实边界

- 全库 760 题已经结构化、建立映射，并通过独立全文核对。
- 来源第一至三章累计 530 题已逐题复核；第四至五章 230 题仍为系统映射。
- 勘误/前提记录总计 178 条；37 道争议题排除自动计分。条目数不等于“178 道答案全错”。

- 图片引用完整性已检查；quiz 题面本身没有图片，不能据此声称全部教材插图已逐张视觉复核。
- 文中测试数量是此前阶段的验收记录，本次整理文档没有重新执行所有网站测试。

## 3. 新课程启动前必须确认的输入

先只读检查现有文件和仓库，再集中询问确实缺少且影响实施的事项。已有明确授权和答案不用反复询问。

| 输入 | 要保存的内容 | 不应擅自推断 |
|---|---|---|
| 课程与使用目的 | 课程名、考试/作业/自学目标、优先章节 | 所有课程都适合刷单选 |
| 本地项目位置 | 用户指定根目录、项目子文件夹 | 当前工作目录就是用户要的目录 |
| 题库来源 | URL/文件、上游版本、格式、资源依赖 | 标“王道”等于官方来源 |
| 笔记依据 | 目录、文件、真实标题层级、补充内容 | 目录序号与来源章节相同 |
| 已学进度 | 用户确认过的章节/小节 | 有笔记或打勾就表示学完 |
| 仓库目标 | 账号、名称、已有/新建、可见性 | 要同步 GitHub 就表示要公开 |
| 发布目标 | 仅本地/局域网/线上，部署平台 | 已有仓库就表示允许开站 |
| 判分规则 | 单选/多选/填空/证明/程序题策略 | 所有参考答案都可自动判分 |
| 保护范围 | 原笔记、实验、用户资料、已有站点 | 构建脚本可以清理整个父目录 |

对于缺少的用户决策，提出具体问题；对于技术事实，先查文件、配置、日志和实际页面。无法确认的内容写入“待确认”，不要编造默认事实。

## 4. 推荐目录与文件所有权

下面是可复用布局，名称可以调整，但必须把原始资料、审核输入、生成数据、网站源码和用户资料分开。

~~~text
<course-exercises>/
├─ AGENTS.md                       项目边界、保护范围、接手顺序
├─ README.md                       当前状态、启动方式、文档索引
├─ requirements.txt / package.json  实际使用的依赖与版本
├─ .gitignore / .gitattributes
├─ THIRD_PARTY_NOTICE.md            来源及第三方许可说明
├─ vendor/<source>/                 固定版本的只读原始快照
├─ app/                            界面源码、本地静态资源
├─ data/
│  ├─ questions.json               提取出的原题数据
│  ├─ source-registry.json         稳定 ID 登记与来源定位
│  ├─ chapters.json / topics.json  课程笔记目录
│  ├─ mappings.json                逐题归属和前置知识
│  ├─ study-defaults.json          已确认学习事实
│  ├─ reviews/                     人工/AI 逐题审核输入
│  └─ overrides/                   勘误与展示、判分覆盖层
├─ scripts/                        盘点、提取、映射、校验、构建
├─ tests/fixtures/                 真实复杂样本与预期结构
├─ tests/browser/                  交互验收
├─ docs/                           计划、执行清单、审核报告、交接
├─ personal/                       用户资料，不自动覆盖
├─ dist/                           构建产物，通常忽略
└─ _work/                          缓存、日志、截图、临时服务记录，忽略
~~~

所有权规则：

- 原始快照按版本更新，不直接打补丁改答案；笔记只读，除非用户另行要求修改。
- 明确每份文件是“维护输入”还是“生成输出”，并写出生成脚本。生成文件不能靠手改维持正确性。
- 本项目第二、三章审核输入是 data/reviews/ch2.json、ch3.json；审核叠加逻辑在 scripts/chapter_review.py，报告和勘误由流程生成。其他课程应重新核实对应关系。
- 临时文件也放项目内，避免交接者不知道哪些外部文件参与了构建。
- 清理目标必须是已确认的项目生成目录，不能包含 personal、vendor 或外部笔记。
- 本机库名、机器绝对路径等配置放被忽略的本地配置，不写进通用前端。

## 5. 阶段一：来源盘点与不可变基线

### 5.1 先盘点，再决定提取器

列出所有来源文件、类型、体积、哈希、引用资源、版本与入口。记录题目边界和答案边界，并人工抽查普通题、长题、表格题、多空题、综合题。

不要假定换门课仍然有 .q 和 details.qa：

| 来源 | 提取策略 | 必须额外检查 |
|---|---|---|
| 静态 HTML | DOM 分区、题块及答案边界 | 独立题块、嵌套列表、脚本依赖 |
| 文本型 PDF | 页码与版面结合提取 | 双栏阅读顺序、公式、跨页题 |
| 扫描 PDF/图片 | OCR 后人工对照 | 正负号、上下标、单位、图注、选项错位 |
| Word/Markdown | 标题、段落、表格等结构解析 | 自动编号、代码块、隐藏答案 |
| 动态网站 | 优先正式导出/API，记录版本 | 权限、分页完整性、异步内容 |

对 PDF 和扫描来源，无法可靠识别的片段保留原图/页码并标为待核对，不能靠 AI 补写“看起来合理”的题面。

### 5.2 建立两个保真概念

1. **原始字节保真**：快照与指定版本完全一致，允许逐文件验证。
2. **提取内容保真**：清洗后的 HTML/JSON 保留题干、选项、解析及结构语义；它本来就不必与原 HTML 字节相同。

本项目对原始层设置：

~~~gitattributes
vendor/** -text
~~~

取得快照时显式防止 Git 换行转换，例如使用 git -c core.autocrlf=false archive。实际命令要结合当前 shell 和归档方式编写，不能把二进制归档经过会改编码的文本管道。

放行条件：版本固定；文件集合与逐文件哈希/字节一致；题量统计有独立依据；资源缺失和许可未知项已记录。

## 6. 阶段二：结构化提取与稳定 ID

### 6.1 提取流程

1. 根据来源章节和实际边界识别题目候选。
2. 分离原题号、题干、选项、答案、解析、年份标签和附图。
3. 保留表格、代码、数学表达式的结构与顺序。
4. 识别题型；不能可靠分类的题先保留为特殊题，不丢弃。
5. 记录原文件、分区、序号/锚点、内容哈希和快照版本。
6. 生成统计并对齐来源题块总数、分章数、分型数。
7. 用独立路径回到原始来源校验全文和有序结构。

HTML 清洗只做明确的安全和展示变换：允许必要标签，去除脚本、事件属性、危险链接；相对图片改为本地引用。每类变换都应记录，不能为了网页好看删除题干的一部分。

普通选项识别应满足明确标记和连续顺序。不要把 I、II、III 陈述列表当作 A、B、C、D 选项，也不要从解析中的某个字母猜答案。

### 6.2 稳定 ID 的规则

题目显示序号用于当前练习顺序，稳定 ID 用于题目身份。两者不能共用。

- 首次导入分配 ID 并登记；后续重建、筛选、乱序不重编号。
- 原来源位置可以更新，题目身份不能因为移动位置改变。
- 重导入先全局按已登记内容匹配，再处理新题，不能先让旧位置抢占 ID。
- 原文变化、重复内容无法唯一匹配、题块拆分/合并，应停止自动迁移该项并人工核对。
- 内容哈希用于发现变更，不能单独解决重复题身份问题。
- 删除的题记录为退役，避免后来把同一 ID 分配给不同题。

本项目实际增加过四项回归：重复导入、题块互换位置、原题内容变化、退役题恢复。其他项目可以复用这些场景，不能直接复用题目 ID。

### 6.3 提取验收不能只比题数

需要同时验证：

- 题数和来源章节总量相符，无重复或孤立答案块。
- 每题题干、选项、答案、解析全文没有截断。
- 表格逐单元格及顺序一致；代码、公式、图片引用的顺序一致。
- 对照样本覆盖长题尾部、嵌套结构、特殊题、跨页和空解析等情况。
- 故意删除尾部、交换表格单元格时，校验器确实失败。

最重要的教训：**题数正确、开头 60 字相同、答案首字母相同，都不能证明无损提取。** 验证器不要只调用导入器自身的同一段逻辑，否则两个地方可能共享同一个错误。

## 7. 阶段三：按真实课程笔记适配

### 7.1 建立笔记目录

读取真实文件和标题，保存文件相对路径、标题层级、行号/锚点和快照哈希。区分正式标题、补充 callout、链接引用和空目录。

不要只读目录标题就推断正文覆盖范围。某知识点只在补充段落出现时，如实映射到该段落，并提示覆盖程度。

### 7.2 每题分别记录归属和前置

- 主章节：练习主要放在哪里。
- 次章节：跨章关联。
- 知识点：题目直接考查的内容。
- 前置知识：解题之前需要的定义、模型、公式或其他章节内容。
- 归属理由：为什么这样分配。
- 额外缺口：现有笔记未明确覆盖的要求。

直接考点与前置集合不一定相同。题目考页表计算，仍可能需要二进制位数、地址单位和硬件模型。

知识点缺口的准确说法是“当前未建立题目关联”或“当前笔记未找到明确覆盖”，不能据此说“这部分永远没有题”。

### 7.3 学习分层与审核状态分开

可采用核心 core、桥接 bridge、补充 supplement、后续 later 等范围；具体含义必须在界面解释。另设审核状态与判分策略。

本项目当前规则：

- 初始学习事实仅第一章。
- 用户本机标记某章已学后，原 later 题可以进入桥接；原核心题仍为核心，补充仍为补充。
- 系统映射徽标继续保留，不能因为学完就假装逐题审核过。
- 争议题单独列组并排除自动判分，不从题库删除。

新课程可以改进这一规则，但必须写明规则和迁移行为，不能悄悄改变已有记录含义。

## 8. 阶段四：逐题审核答案和勘误

### 8.1 一道题的完整审核单

每题至少留下以下信息，而不是只写一句“正确”：

1. 稳定 ID、原题内容哈希、来源位置。
2. 完整读过的题干、选项、原答案和解析。
3. 自己的结论和推导，必要时复算或构造反例。
4. 结论所依赖的教材模型、定义和隐含条件。
5. 主次章节、真实知识点、前置和笔记定位。
6. 证据来源或独立计算的检查 ID。
7. 审核状态、勘误类型、对自动计分的影响。
8. 审核日期和未解决问题。

本项目审核状态语义：

| 状态 | 含义 | 一般处理 |
|---|---|---|
| verified | 本轮未发现实质问题 | 在既定题型和判分规则下使用 |
| qualified | 原答案在声明模型下沿用，需补前提或纠正解析 | 展示前提；保留原答案 |
| disputed | 题面有误、条件不足、结论不唯一等 | 不自动计分，保留原始内容与争议 |
| 尚未逐题审核 | 仅有提取或系统映射 | 如实标识，不借用前三类的可靠性 |

verified 不是“官方认证永远正确”。教材、架构、版本或题面改变后仍要重新审查。

### 8.2 用独立计算解决可计算的争议

先写清模型，再复算。例如：

- OS：调度时间线、信号量初值与可达状态、死锁安全序列、地址转换、缺页次数。
- 其他课程：按课程实际选择可独立验证的数值或算法问题，不照搬 OS 计算器。

复算建议：

- 写清单位、边界、初始状态、并列选择规则和舍入条件。
- 适合时使用整数或有理数，避免浮点误差造成假分歧。
- 对关键算法用独立方法交叉验证，而不是复制同一个实现两遍。
- 有限枚举可以发现反例；没有发现反例不等于一般性证明。
- 缺少决定答案的条件时，记录条件不足，不能替题面偷偷补上。
- 引用外部技术事实时优先正式教材、官方文档、原论文等一手来源，保存具体章节与版本；网络资料实际打开核查后再引用。

### 8.3 勘误独立保存

原答案不可被审核结论直接覆盖。勘误应包含原答案、问题、证据、适用前提、建议展示和判分策略。

概念性示例，**不是要求其他项目直接使用本项目现有 JSON schema**：

~~~json
{
  "questionId": "stable-id",
  "sourceContentHash": "sha256:<actual-hash>",
  "answerReview": {
    "status": "qualified",
    "conclusion": "在明确声明的模型下沿用原答案",
    "evidenceRefs": ["source-or-check-id"]
  },
  "mapping": {
    "primaryChapterId": "course-chapter-id",
    "topicIds": ["actual-topic-id"],
    "prerequisiteTopicIds": ["actual-prerequisite-id"]
  },
  "errata": [
    {
      "kind": "missing_assumption",
      "issue": "原解析遗漏的具体前提",
      "scoring": "按本项目定义的合法枚举填写"
    }
  ]
}
~~~

本项目审核输入绑定 sourceContentHash；来源变动时拒绝无条件复用旧审核。新课程也应建立类似失效机制。

### 8.4 批次完成的证据

为整章建立一题一行/一条记录，校验审核 ID 集合等于该章题目集合，不能仅凭总条数相等。状态之和应等于题数；每个知识点和前置 ID 必须存在；勘误和独立检查应能定位回题目。

不要只检查“带勘误的题”，其余题仍要有逐题结论。报告应明确来源章与课程章的区别。

## 9. 阶段五：先实现可用的练习闭环

### 9.1 首章最小闭环

先实现真实使用路径，再做全库装饰：

~~~text
章节入口 → 题单与范围 → 当前题 → 选择/草稿
          → 提交或查看参考答案 → 判分/自评与解析
          → 上下题/题号跳转 → 错题回顾 → 重做
          → 刷新恢复 → 导出与导入
~~~

- 普通单选按合法答案自动判分；多空、综合、证明题按真实结构设计交互。
- 自评不能伪装成客观自动评分；没有可靠判分依据的题保留练习能力。
- 作答前只展示不泄露答案的范围、知识点和前置提示。
- 归属理由、审核结论、勘误也可能泄露答案，必须一起检查。
- 进入已提交题后恢复解析和选项；争议题不画成“答对/答错”。

### 9.2 导航和路由

- 长解析页面在题卡底部提供上一题、下一题、题号跳转，避免反复滚回顶部。
- 顶部和底部共用一个渲染/事件逻辑，保持当前序号、范围、禁用状态一致。
- 第一题禁用上一题，最后一题禁用下一题；无效题号给出明确反馈。
- 回车在题号输入框中执行跳转，不能同时提交当前答案。
- 键盘事件离开页面时释放，原生按钮/链接保留正常键盘行为。
- 路由异步加载加版本守卫，快速切页不能让旧请求覆盖新页面。
- URL 携带稳定题目 ID；筛选后列表缩短，也能准确定位目标。

本项目曾出现“答对一道错题后，错题列表减少，再按数组下标推进跳过下一题”。解决点是保存目标题的稳定 ID，不是反复修正下标。

### 9.3 搜索、布局、公式与离线

- 搜索完整题干、知识点、章节名；展示真实总量，渲染截断要明确提示。
- 章节、题型、有效分层等筛选使用统一规则，避免题单、搜索、单题各算一遍。
- 桌面和窄屏检查题卡、表格、长公式、按钮换行及侧栏焦点。
- 公式库和字体本地化后，实际断网验证；文件在仓库中不代表浏览器已请求成功。
- 使用 HTTP 服务访问，不能只双击带 fetch/模块脚本的 index.html。
- 同时检查根路径和 /<repo>/ 子路径，不能在本地正常、Pages 资源全失效。

静态站适合本项目的个人练习需求。其他课程如果需要登录、跨设备同步、程序评测或教师后台，应重新确定架构，不能声称本项目已经具备这些能力。

## 10. 阶段六：保护学习记录与兼容性

### 10.1 记录按稳定题目 ID 保存

至少明确首次作答、最近结果、累计轮次、所选选项、自答草稿和自评的含义。重做打开新一轮，不等于删除历史；修改同一轮自评也不应虚增次数。

本项目使用独立命名空间 os-exercises:v1，不读写原站 os408-*。其他课程必须换成自己的命名空间，防止互相污染。

### 10.2 导入先完整校验，再一次合并

验证 schema、数据类型、合法题目 ID、时间、次数、计分方式和枚举范围。已知题目中任一记录损坏，应拒绝整份导入，不能先写一半再失败。

本项目当前合并规则包括：未知题目 ID 跳过并计数、最近结果按时间合并、保留首次历史和累计次数、迁移已学章节标记。其他项目要明确冲突策略，不能直接猜测跨版本兼容。

不认识的 schema 或损坏本机数据应保留原数据并告警，不能当空数据覆盖。存储不可用时可以用内存继续练，但必须持续告知未持久化。

### 10.3 审核策略变化不应抹掉历史

一道题过去可自动判分，现在改为争议时：

1. 原始记录仍可导出。
2. 当前显示和统计按照新策略计算。
3. 旧自动分数不再影响当前正确率、错题范围。
4. 保留必要的历史兼容校验，只允许明确的旧规则，不能因此放宽所有导入。

这是“保存历史事实”和“采用当前判分策略”两个层次。不要通过清空用户记录来解决策略升级。

本地地址、端口、线上域名不同会形成不同 origin，记录不会自动共享。换端口看不到记录时，先核对 origin，再排查存储损坏。

## 11. 阶段七：分层验证与放行标准

| 层级 | 主要检查 | 不能宣称的结论 |
|---|---|---|
| 来源 | 文件集合、全部字节/哈希、资源引用 | “原答案一定对” |
| 提取 | 全题全文、答案解析、表格/代码/公式顺序 | “语义已经权威审校” |
| 数据 | ID 唯一、集合覆盖、合法引用、审核哈希、统计 | “界面不会出问题” |
| 独立复算 | 数值、算法、反例、模型前提 | “有限枚举证明一般定理” |
| 单元回归 | 稳定 ID、变更拒绝、校验器能抓注入错误 | “用户全流程可用” |
| 浏览器 | 作答、恢复、迁移、错题、搜索、快捷键、布局 | “所有浏览器和真机均通过” |
| 发布 | 远端版本、CI、线上页面和资源 | “推送成功就等于上线成功” |

最少包含这些真实流程：

- 答对、答错、综合题草稿和自评；刷新后恢复。
- 重做不丢首次历史；同轮自评次数不膨胀。
- 错题答对后列表缩短，仍能连续推进。
- 损坏导入整体拒绝，原记录不变；未知 schema 不覆盖。
- 已学标记随导出导入迁移。
- 争议题不自动计分，历史分数退出当前统计。
- 作答前 DOM 中的审核区域不泄露答案。
- 快速切页、畸形路由、存储不可用和损坏。
- 390px 等窄屏、深色、长题；离线公式；子路径部署。
- 控制台错误、资源 4xx/5xx 和关键截图。

测试使用独立浏览器上下文或测试命名空间，不能清空用户实际学习记录。记录运行命令、浏览器、URL、提交、日期、通过项及未验证平台。

只给低影响文档或样式做小改动时，不需要机械地重跑所有数学复算；选择与影响范围相符的验证。涉及提取、ID、判分或存储时，则必须覆盖对应数据和迁移风险。

## 12. 阶段八：同步 GitHub 与发布

仓库同步与公开网站是两个决定。先确认账号/仓库及可见性；没有公开授权时，不因为部署便利而切换 public。

推荐发布顺序：

1. 保存基线，查看 git status，确认没有误带用户资料或未合并修改。
2. 完成适用校验与构建，检查被忽略的本机配置和临时目录。
3. 更新当前状态、执行清单、来源说明和未完成范围。
4. 只暂存本轮预期文件，检查 diff，再提交。
5. 推送后核对远端 HEAD 与本地一致。
6. 检查对应提交的构建/部署工作流成功，不只看任务已排队。
7. 打开实际线上 URL，核对新行为和关键资源；保存线上验收证据。

本项目的 dist 不提交，由 .github/workflows/deploy-pages.yml 构建。工作流执行构建、数据校验、Python 回归后发布；浏览器验收并未全部放进该 CI，不能声称 Actions 绿灯就等于跨浏览器全部重跑。

比较 Windows 本地与 Linux 构建的生成 JSON 时，应根据目标决定比较方式：题目语义比较解析后的对象；原始 vendor 仍要逐字节一致。不要把生成文件的 CRLF/LF 差别误报成答案变化，也不要用忽略换行掩盖原始快照被改。

保留第三方来源与许可说明。上游无 LICENSE 不等于可以把整套题库重新标成自己原创或给整库套 MIT。本项目公开这一历史事实不构成对其他来源的授权。

## 13. 实际踩坑清单

| 现象 | 原因/错误判断 | 本项目处理与可复用经验 |
|---|---|---|
| 对话“读成功”却看不到正文 | 返回的是引用标记 | 看实际正文；针对指定对话排障，不编造历史 |
| 题量少 47 道 | 只选择 .q 容器 | 按答案边界和独立综合题补全，核对 760 |
| 题面看着没问题但仍有遗漏 | 只核对开头或总字符数 | 全文加有序结构；注入尾部删除/表格交换验证 |
| 多空题被判错 | 硬套单字母单选规则 | 显式题型与自评，不猜判分 |
| vendor 审计不一致 | Windows 自动换行转换 | 控制 Git 文本转换，逐 blob/字节验证 |
| 重排后学习记录串题 | 用数组下标/位置当身份 | 冻结 ID；全局内容匹配后再处理位置 |
| 有笔记就算已学 | 混淆资料存在与学习事实 | 已学状态单独由用户确认 |
| 第一章出现多种题量 | 来源章、课程章、争议分组口径混用 | 明确统计口径和交集，保存总量守恒 |
| “桥接”被理解成审核标志 | 学习范围与可靠性混在一起 | 分开显示范围、审核和计分 |
| 重做后首次记录/草稿消失 | 直接删除记录 | 新轮次状态与持久历史分离 |
| 错题练习跳过下一题 | 答对后列表缩短，下标变了 | 以目标稳定 ID 跳转 |
| 导入失败但数据已改一半 | 边解析边写入 | 整体校验后原子合并 |
| 后来争议的旧题仍影响正确率 | 只改新作答，不处理读取统计 | 原始历史保留，当前统计投影排除 |
| 作答前就能猜出答案 | 审核结论/归属理由提前展示 | 所有答案性说明随解析展开 |
| 旧页面覆盖新页面 | 异步请求完成顺序不同 | 路由版本守卫，清理事件监听 |
| 输入题号按回车却提交答案 | 全局快捷键与原生控件冲突 | 按焦点与事件来源分流 |
| 断网公式坏了 | JS 本地，字体仍走 CDN | 检查实际网络请求并离线验收 |
| Pages 白屏、本地正常 | 根路径写死或直接双击测试 | HTTP 与仓库子路径均验证 |
| 移动端侧栏关闭仍挡点击 | 仅移出画面但未隐藏 | 检查可见性、焦点、遮罩和 Escape |
| 窗口/AI 之间互相覆盖 | 多个写入者修改同一批文件 | 备份现状，暂停冲突写入后整合 |
| 接手者重复已经做过的事 | 历史计划没标状态，交接过时 | 当前状态置顶，标历史计划、未完成和精确证据 |
| 推送了就报上线 | 把 Git、CI、部署当一件事 | 分别核对版本、工作流和线上行为 |

### 14.3 新课程应改什么

可以借鉴：分层架构、稳定 ID 思路、校验场景、练习交互、迁移规则、文档结构。

必须改或重新验证：

- 来源解析器、资源路径、题型和答案结构。
- 来源版本和统计基准，不能保留 760、5 章等 OS 常量。
- 课程章节、笔记目录、知识点 ID、前置、学习默认值。
- 审核结论、计算模型和证据，不能批量改课程名后复用。
- 应用标题、仓库、发布路径、localStorage 命名空间、导出标识。
- 依赖版本、公式/代码显示、单位及特殊符号。
- 许可说明、本机配置和用户保护范围。
- 测试预期和复杂样本；不是把数字改到测试变绿。

## 16. 每阶段完成检查表

### 启动和计划

- [ ] 根目录、来源、笔记、保护范围已核实；缺少的用户决策已列明。
- [ ] 原仓库和工作区现状已记录；没有覆盖已有修改。
- [ ] 计划和执行清单已落到文件，每阶段都有具体交付物与放行标准。

### 来源和提取

- [ ] 来源版本固定；文件集合、字节/哈希与资源检查通过。
- [ ] 每类题块都有提取路径，特殊题没有被丢弃或硬套单选。
- [ ] 总题量、分章和分型守恒；全文与有序结构独立检查通过。
- [ ] 稳定 ID 的重导入、移动、内容变化、重复歧义处理已验证。

### 映射和审核

- [ ] 章节/知识点来自真实笔记，主次归属、前置和缺口分开保存。
- [ ] 学习事实有用户依据，系统映射和逐题审核状态没有混淆。
- [ ] 本轮审核 ID 集合覆盖目标全章；每题有可追溯结论。
- [ ] 原答案保留；勘误单独保存，条件和计分影响明确。
- [ ] 可计算争议已复算，未解决事项明确，不虚称权威认证。

### 网站和记录

- [ ] 首章作答、解析、自评、刷新、错题、重做、导入导出闭环可用。
- [ ] 争议题与旧记录策略一致；作答前不泄露答案性说明。
- [ ] 快捷键、稳定 ID 导航、列表缩短、异步换页和存储失败已验证。
- [ ] 窄屏、公式字体、断网、子路径与资源错误已检查。

### 同步和交接

- [ ] 暂存文件范围正确，无本机配置、用户记录或不该公开的资料。
- [ ] 若已授权同步，远端提交与本地一致；若已授权发布，工作流和线上均核验。
- [ ] 文档标注当前状态、日期、证据、未完成范围，不把历史计划当现状。
- [ ] 下一对话拿到的文件不依赖本聊天才能理解。

## 17. 交接文件怎么写才不会失效

在 docs/AI实施交接.md 等固定入口中，把以下内容放在顶部：

~~~text
1. 当前目标与本轮范围。
2. 当前项目路径、分支、源码基线；可见性/发布方式及其确认依据。
3. 来源版本、数据 schema、题量与原始快照校验结果。
4. 哪些是维护输入，哪些由什么命令生成。
5. 已完成阶段、最近变更、未提交修改及不能覆盖的文件。
6. 逐题审核覆盖范围、争议策略和还没审核的范围。
7. 实际测试命令、环境、结果文件、截图和已知限制。
8. 本地启动、构建、同步和发布的准确操作。
9. 待确认决策、阻塞和下一步，按优先顺序。
10. 保护范围、第三方来源、配置和记录迁移约束。
~~~

避免这些写法：

- “功能基本完成”“全库已审核”，却没有覆盖集合和结果。
- “最新提交就是某 SHA”，却不知道后面还有新提交。应给核对命令并注明记录时点。
- 保留旧的“私有”“尚未实现”等表述，却没有标历史状态。
- 文档只指向聊天记录，关键文件和命令没有写出来。
- 把所有累计日志堆在一起，读者无法分清最新状态。

维护时保留历史证据，在顶部写当前结论；发生范围变化时明确哪段旧状态已被替代。本项目的原始实施计划就是历史计划，当前接手需同时看执行清单、审查报告和真实源码。

## 18. 其他课程复制时的实施顺序

第一轮只读调查并落地计划，确认来源、笔记、版本、目录和保护范围。

第二轮固定来源、完成提取和独立保真校验；题目尚未审核时如实标注。

第三轮对齐真实课程结构，逐题完成已学首章映射、审核和前置，建立最小练习闭环。

第四轮做独立审查，优先修复保真、ID、计分和记录问题，再完善搜索、布局和导航。

第五轮按来源章节逐批审核，保存逐题证据和独立复算，不因全库已导入就跳过未审部分。

第六轮在已授权范围内同步和发布，每次都核对实际版本与线上结果，并更新交接入口。

其他课程应复用的是这套证据和推进方法。具体章节、题型、模型、答案和完成状态，始终由那门课的真实文件和实测结果决定。
