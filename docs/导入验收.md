## 2. 提取方法与关键取舍

1. **边界不依赖 `.q` 容器。** 扫描 `article` 的顶层子节点，识别三类题目起点：
   `div.q`（713 道）、`<p><strong>第 N 题</strong>`（ch1 综合应用题 2 道）、
   `<h3>第 N 题…</h3>`（ch2 综合应用题 45 道）。因此 760 道全部落到题目实体，
   其中 **47 道没有 `.q` 容器**，与调查基线一致。
2. **陈述列表不是选项。** `Ⅰ./Ⅱ./Ⅲ.` 与选项同用 `<p class="mono">`。
   解析时先按 `A.`～`H.` 标记判断：无标记或标记不从 A 开始且不连续者，保留在题干中。
3. **题号标签转为结构化字段。** `<strong>第 N 题</strong>` 从题干剥离，写入
   `source.originalLabel`，避免界面重复显示题号；题干其余内容一字不改。
4. **解析块单独存放。** `details.qa` 内的 `答案：` 与解析过程分离为
   `originalAnswer` / `originalExplanationHtml`，答案标签本身不重复出现在解析里。
5. **白名单清洗。** 只保留 `p/br/strong/em/sup/sub/span/div/ul/ol/li/table/caption/
   thead/tbody/tr/th/td/pre/code/blockquote/hr/img/a` 与
   `mono/callout/callout-title/tip/notice` 等受控 class；移除脚本、事件属性、
   `javascript:` 链接、外部 `http(s)` 资源与 `data-*`、`id`、`style`。
6. **ID 冻结。** 形如 `c1-s3-0-q009`：章 + 第几个 H2 分区 + 第几个 H3 子分区（无则 0）
   + 原题号。首次写入 `data/source-registry.json` 后即为权威；重跑时优先复用登记表 ID，
   内容哈希用于发现变更。上游重排导致定位变化但内容哈希一致时沿用旧 ID 并记录迁移。
